# T3 — Launcher + Güvenlik Kapısı (Runly.exe)

**Model: Opus** · Bağımlılık: T2 · T4 ile paralel yürütülebilir · Tahmini süre: 2-3 saat

> `docs/SPEC.md` §6, §7, §8 bu paketin şartnamesidir. Bu, projenin **en riskli** parçası:
> kullanıcının makinesinde keyfi kod çalıştıran bileşen. Güvenlik kapısını zayıflatan hiçbir
> "kolaylık" ekleme.

## T2 ve T4'ten gelen bağlayıcı notlar

- **Servisleri elle bağla, DI konteyneri yok:** `new ConfigStore()`, `new TrustStoreService()`,
  `new PathSearcher()`, `new MotwService()`, `new ScriptInspector(motwService)`,
  `new SecurityGate()`, `new InterpreterResolver(pathSearcher)`, `new ProcessLauncher()`,
  `new FileLogger(config.LogEnabled)`.
- **Karar K11 — en kolay unutulan şey:** `TrustFile`/`TrustFolder` sadece belleği değiştirir.
  Kullanıcı "her zaman güven" dedikten sonra **`trustStore.Save()` çağırmazsan güven kaybolur**
  ve kullanıcı her açılışta aynı soruyu görür. Bunu elle test et.
- `SecurityGate` saf: `TrustStoreService.Load()` ile doldurup öyle ver.
- `MotwService` ve `ProcessLauncher` `[SupportedOSPlatform("windows")]` işaretli; çağıran kodun da
  öyle olması gerekir yoksa CA1416 build'i kırar (warnings-as-errors).
- `ResolvedInterpreter.CommandLine` diyalogda gösterilecek tam komut satırını hazır veriyor.
- `RunlyRegistryLayout` (T4) `--verb` değerlerini `run`/`runas`/`edit`/`prompt-args` olarak yazdı;
  CLI ayrıştırıcın bunlarla birebir uyuşmalı yoksa sağ tık menüsü çalışmaz.
- `Runly.Core/Shell/` ve `Runly.Core/Services/` **tamamlanmış ve onaylanmış** alanlardır,
  dokunma. Senin alanın sadece `src/Runly.Launcher/`.

## Görev

`src/Runly.Launcher` içinde `Runly.exe`'yi tamamla: argüman ayrıştırma, güvenlik diyaloğu,
fiil işleme, süreç çalıştırma, pencere yönetimi.

## Yazılacaklar

### `Program.cs` — akış
```
1. Argümanları ayrıştır (SPEC §7). Hatalıysa kullanım metni + exit 2.
2. Config + TrustStore yükle (T2 servisleri).
3. ScriptInfo = inspector.Inspect(path). Dosya yoksa hata diyaloğu + exit 2.
4. Verb == Edit ise: editörü aç, exit 0. (Güvenlik kapısı YOK — çalıştırma yok.)
   Karar K7: `editorCommand` boşsa veya PATH'te bulunamazsa `notepad.exe`'ye düş.
   Bu sabit `Ui/EditorLauncher.cs`'te tutulur, Core'a konmaz.
5. Interpreter çöz. Source == None ise: "yorumlayıcı ayarlı değil" diyaloğu
   ("Ayarları aç" butonu RunlySettings.exe'yi başlatır) + exit 3.
6. Güvenlik kapısı: verdict = gate.Evaluate(...).
   - Trusted → devam
   - NeedsPrompt / Changed / MotwBlocked → diyalog göster
     - Kullanıcı iptal → exit 4
     - RememberFile/RememberFolder işaretliyse trust store'a yaz
     - StripMotw işaretliyse ADS'yi sil
7. Verb == PromptArgs ise argüman kutusu göster, çıkan argümanlarla interpreter'ı yeniden çöz.
8. Süreci başlat (elevated = Verb == RunAs). Süreyi ölç.
9. keepWindowOpen kuralına göre bekle.
10. Child'ın exit code'unu aynen döndür.
```

### `Ui/TaskDialogInterop.cs` — `IDialogService` implementasyonu

`comctl32.dll` → `TaskDialogIndirect` P/Invoke. AOT-uyumlu (`[LibraryImport]` tercih et).
Gereken yapılar: `TASKDIALOGCONFIG`, `TASKDIALOG_BUTTON`, `TASKDIALOG_FLAGS`, callback delegate.

**Zorunlu:** `app.manifest` içinde comctl32 v6 assembly bağımlılığı olmalı, yoksa
`TaskDialogIndirect` `E_INVALIDARG` veya entry-point hatası verir. Manifest ayrıca
`dpiAware`/`dpiAwareness` (PerMonitorV2) ve `longPathAware` içersin. `requestedExecutionLevel`
= `asInvoker` (elevated çalıştırma ShellExecute ile yapılır, manifest ile değil).

**Güvenlik diyaloğu içeriği (SPEC §6):**
- Başlık: `Runly — Script çalıştırılacak`
- Ana ikon: `NeedsPrompt` → shield/uyarı · `MotwBlocked` → hata (kırmızı) · `Changed` → uyarı
- Ana talimat:
  - `NeedsPrompt`: `"{dosyaadı}" çalıştırılsın mı?`
  - `MotwBlocked`: `"{dosyaadı}" internetten indirilmiş`
  - `Changed`: `"{dosyaadı}" son onaydan sonra değişti`
- Gövde: tam yol · boyut · değiştirilme tarihi · **çalışacak tam komut satırı** (monospace olamaz,
  ayrı satırda ver)
- Genişletilebilir alan ("Kodu göster"): ilk 100 satır. **Karar K5:** kod gösterimi bu
  genişletilebilir alanla yapılır, ayrı diyalog turu yok — `SecurityDecisionReason.CodeRequested`
  sözleşmede var ama döndürülmeyecek.
- Butonlar: `Çalıştır` (varsayılan **değil**) · `İptal` (varsayılan, Esc)
- Onay kutuları (verdict'e göre):
  - `NeedsPrompt`/`Changed`: `Bu dosyaya her zaman güven` ve `Bu klasördeki her şeye güven`
    (TaskDialog tek checkbox destekler → radio buton grubu kullan:
    `Sadece bu sefer` / `Bu dosyaya her zaman güven` / `Bu klasöre her zaman güven`)
  - `MotwBlocked`: checkbox `İnternet işaretini kaldır`
- `MotwBlocked` durumunda `Çalıştır` butonuna 3 saniyelik gecikme koy (buton başta devre dışı,
  callback timer ile etkinleşir) — refleksle onaylamayı engeller.

**Argüman kutusu:** TaskDialog input alanı desteklemez. Bunun için basit bir Win32 dialog
(`CreateWindowExW` + EDIT control) yaz **veya** daha pratiği: `RunlySettings.exe --ask-args`
alt-sürecini çağırıp stdout'tan oku. İkincisini seçersen T5'e bağımlılık doğar — raporda belirt.
Öneri: küçük bir native input dialog yaz, 150 satırı geçmez.

### `Ui/ConsoleWaiter.cs`
- `keepWindowOpen` kuralı. Bekleme satırı:
  `--- Çıkış kodu: {code} ({saniye:F1} sn) — kapatmak için bir tuşa basın ---`
- Renk: exit 0 → yeşil, değilse kırmızı. `Console.ReadKey(intercept: true)`.
- Konsol yönlendirilmişse (`Console.IsOutputRedirected`) bekleme yapma.

### `app.manifest` + `Runly.Launcher.csproj`
- `PublishAot`, `InvariantGlobalization`, `StackTraceSupport=false`, `UseSystemResourceKeys=true`
- `ApplicationManifest`, `ApplicationIcon` = `assets/runly.ico` (yoksa T6'da gelecek, şimdilik atla)
- `AssemblyName` = `Runly`

### Global exception handler
Yakalanmayan her istisna → hata diyaloğu (`Runly beklenmedik bir hatayla karşılaştı` +
exception mesajı + log yolu) ve log'a yaz. Stack trace kullanıcıya gösterilmez, log'a yazılır.

## Kabul kriteri

- `dotnet publish src/Runly.Launcher -c Release -r win-x64 /p:PublishAot=true` → tek exe,
  **AOT/trim uyarısı sıfır**, boyut < 5 MB.
- Elle test (samples klasörü yoksa kendin geçici dosya üret):
  1. `Runly.exe hello.js` → diyalog çıkar, `Çalıştır` → çıktı görünür
  2. Aynı dosya "bu dosyaya her zaman güven" ile → 2. çalıştırmada diyalog çıkmaz
  3. Dosyayı değiştir → "değişti" diyaloğu çıkar
  4. `echo` ile MOTW ekle (`Add-Content -Path x.js -Stream Zone.Identifier -Value "[ZoneTransfer]`nZoneId=3"`) → kırmızı diyalog + 3 sn gecikme
  5. Hata veren script → pencere açık kalır, kırmızı çıkış kodu satırı
  6. `Runly.exe --verb edit hello.js` → editörde açılır, çalışmaz
  7. Türkçe karakterli ve boşluklu yol → sorunsuz
- Soğuk başlangıç ölçümü: `Measure-Command` ile ölç, raporla (hedef < 50 ms, diyalog hariç).

## Yapma

- `Runly.Core` veya `src/Runly.Settings` altındaki dosyaları değiştirme. Core'da eksik bir şey

- stdout/stderr redirect etme.
