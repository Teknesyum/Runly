**Model: Sonnet** · Bağımlılık: T1 · Tahmini süre: 2-3 saat

## Görev

T1'de tanımlanan arayüzlerin `Runly.Core` içindeki gerçek implementasyonlarını yaz ve test et.
UI ve registry **bu pakete dahil değil** (T3/T4'te).

## Yazılacak sınıflar

### `Services/ConfigStore.cs` — `IConfigStore`
- `%APPDATA%\Runly\config.json` oku/yaz, source-generated JSON context ile.
- Dosya yoksa `DefaultConfig.Create()` yaz ve dön.
- **Bozuk JSON:** `config.json.bak` olarak yeniden adlandır, varsayılanı yaz, dön. Asla throw etme.
- `version` beklenenden küçükse basit bir migration hook'u bırak (şimdilik no-op).
- Atomik yazma: geçici dosyaya yaz → `File.Move(overwrite: true)`.

### `Services/TrustStoreService.cs` — `ITrustStore`
- `trust.json` oku/yaz, aynı dayanıklılık kuralları.
- `IsTrusted(ScriptInfo)`: önce klasör eşleşmesi (case-insensitive, normalize edilmiş tam yol,
  alt klasörler dahil — `C:\A` güveniliyorsa `C:\A\B\x.js` de güvenilir; ama `C:\AB` **değil**),
  sonra dosya yolu + SHA-256 eşleşmesi.
- `TrustFile` hash'i kaydeder. Aynı yol tekrar eklenirse hash güncellenir.

### `Services/PathSearcher.cs` — `IPathSearcher`
- `where.exe` çalıştırma. `PATH` + `PATHEXT` üzerinden manuel tarama.
- Verilen isim zaten mutlak yolsa doğrudan `File.Exists` kontrolü.
- **Store stub filtresi:** bulunan dosyanın boyutu 0 ise o adayı atla, aramaya devam et
  (`%LOCALAPPDATA%\Microsoft\WindowsApps` reparse point'leri için — SPEC §8).
- Sonuçlar `RunlyPaths.CachePath`'te (= `%LOCALAPPDATA%\Runly\ipcache.json`, karar K2)
  24 saat cache'lenir; cache girişi bayatsa
  veya işaret ettiği dosya artık yoksa yeniden aranır.

### `Services/ScriptInspector.cs` — `IScriptInspector`
- Boyut, son değişiklik (UTC), SHA-256 (streaming, dosyayı tamamen belleğe alma).
- İlk 100 satır (veya 64 KB, hangisi önce gelirse) — BOM'a saygılı, UTF-8 varsayılan.
- Shebang: ilk satır `#!` ile başlıyorsa ayrıştır. `#!/usr/bin/env node -X` → `node`.
  Ham satırı `ScriptInfo.Shebang`'e, ayrıştırılmış ismi `ScriptInfo.ShebangInterpreter`'a yaz.
  **Karar K4:** inspector PATH'e BAKMAZ. `python3` → `python` fallback'i resolver'ın işidir.
  Windows yol ayracını da kabul et.
- MOTW bilgisini `IMotwService`'ten al.
- 100 MB'tan büyük dosyada hash hesaplama (çok yavaş) — `Sha256 = null` dön, `IsTrusted` bunu
  "güvenilmez" sayar.

### `Services/MotwService.cs` — `IMotwService`
- `path + ":Zone.Identifier"` alternate data stream'ini oku (`CreateFileW` P/Invoke veya
  doğrudan `FileStream` ile ADS yolu — hangisi çalışıyorsa; ADS yolu .NET'te `FileStream` ile
  açılabilir).
- `ZoneId=3` (İnternet) ve `ZoneId=4` (Güvenilmeyen) → MOTW var sayılır. `ZoneId<=2` → yok.
- `Strip`: `DeleteFile(path + ":Zone.Identifier")` P/Invoke.
- Dosya sistemi ADS desteklemiyorsa (FAT32/ağ sürücüsü) → sessizce "MOTW yok" dön, loglama yap.

### `Services/SecurityGate.cs` — `ISecurityGate`
SPEC §6'daki sırayı **birebir** uygula:
1. MOTW varsa → `MotwBlocked` (securityMode'a bakma).
2. Güvenilen klasördeyse → `Trusted`.
3. Güvenilen dosya + hash uyuyorsa → `Trusted`. Hash uymuyorsa → `Changed`.
4. `securityMode == NeverAsk` → `Trusted`. Aksi halde → `NeedsPrompt`.

Bu sınıf saf fonksiyon gibi olmalı — hiçbir IO yapmaz, verilen `ScriptInfo` üzerinden karar verir.
Testlerin çoğu buraya yazılacak.

### `Services/InterpreterResolver.cs` — `IInterpreterResolver`
- Sıra: shebang → config eşlemesi → yok (`Source = None`).
- **Karar K4:** shebang fallback zinciri buradadır. `ShebangInterpreter` PATH'te bulunamazsa
  bilinen alternatifleri dene (`python3`→`python`→`py`, `node`→`nodejs`), sonra config'e düş.
- Argüman şablonundaki `{script}`, `{args}`, `{dir}` yer tutucularını doldur.
- `{args}` doldurulurken her argüman gerekiyorsa tırnaklanır (boşluk/tırnak içerenler).
  Windows argüman kaçışını doğru yap: içerideki `"` → `\"`, sondaki `\` çiftlenir.
- `.ps1` için `-ExecutionPolicy Bypass` yalnızca çağıran öyle istediğinde eklenir —
  bu bilgi config'deki şablondan gelir, resolver şablona müdahale etmez.

### `Services/ProcessLauncher.cs` — `IProcessLauncher`
- `elevated == false`: `ProcessStartInfo` + `UseShellExecute = false`, **redirect YOK**
  (SPEC §7 — child aynı konsolu kullanmalı). `WorkingDirectory` = script klasörü.
  `WaitForExit()`, `ExitCode` dön.
- `elevated == true`: `UseShellExecute = true`, `Verb = "runas"`. Kullanıcı UAC'yi reddederse
  `Win32Exception` (1223) → `ExitCode.UserCancelled` dön, throw etme.
- Süreç başlatılamazsa (dosya yok vb.) → `ExitCode.NoInterpreter`.

### `Services/FileLogger.cs` — `ILogger`
- `%APPDATA%\Runly\runly.log`, format `2026-08-09T14:12:30.123Z [INFO] mesaj`.
- 1 MB'ı geçince `runly.log.1`'e taşı, yenisini aç (tek dosyalık rotasyon yeter).
- `logEnabled == false` ise no-op. Loglama hatası **asla** uygulamayı düşürmez (try/catch yut).

## Testler (`tests/Runly.Core.Tests`)

En az şunlar — hepsi gerçek dosya sistemine dokunmadan, geçici klasör veya fake ile:
- `SecurityGateTests` — SPEC §6'daki 4 dalın her biri + `NeverAsk`'in MOTW'yi atlamadığı.
- `InterpreterResolverTests` — shebang önceliği, config fallback, `{script}/{args}/{dir}`
  doldurma, boşluklu yol tırnaklanması, tırnak kaçışı.
- `PathSearcherTests` — 0-byte stub atlama, cache bayatlama.
- `TrustStoreTests` — klasör prefix tuzağı (`C:\A` vs `C:\AB`), hash değişimi.
- `ConfigStoreTests` — bozuk JSON kurtarma, round-trip, atomik yazma.
- `ScriptInspectorTests` — shebang varyantları, BOM'lu dosya, boş dosya.

Hedef: `Runly.Core` üzerinde anlamlı kapsam; her public metodun en az bir mutlu + bir hata yolu.

## Kabul kriteri

- `dotnet build -c Release` sıfır warning.
- `dotnet test` tamamı yeşil.
- `Runly.Core`'da tek bir `Console.` çağrısı yok (grep ile doğrula).
- AOT publish hâlâ çalışıyor: `dotnet publish src/Runly.Launcher -c Release -r win-x64 /p:PublishAot=true`
  — trim/AOT uyarısı çıkarsa **düzelt**, bastırma.
